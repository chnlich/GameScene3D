# GameFrame3D 演示脚本

目标：让评委探索已经完成的三维 demo，并通过真实证据辨认 Astra 判断对输出的实际作用。

当前状态：演示准备草稿。当前素材包有七张候选输入和一个已有双人交手 GLB；该场景姿态经人工修订，尚无本次新流程生成或自动修正的成果证据。素材与许可见 ../materials/catalog.json 和 ../materials/ATTRIBUTION.md，工程接口见 ../../contracts/scene.schema.json。文件核验不代表集成页面已经验证通过。

三分钟现场只展示已经完成、可以交互的 demo；一分钟视频也围绕完成结果组织。pipeline 是团队内部真实的演前准备工具，用于生成场景、检查输出、保存调用与修正证据。现场和成片均不安排上传、提交任务或等待生成。实际新增成果须在演前完成并核实后纳入，不能把旧场景当作新流程证据。

## 一分钟视频

| 片内时间 | 屏幕动作 | 台词与字幕 | 所需证据 |
| --- | --- | --- | --- |
| 0–7 秒 | 打开已完成场景，旋转至侧面 | 「GameFrame3D，让静止画面中的场景可以换角度查看。」持续标注「预生成示例」；旧场景另标「已有预生成场景，姿态经人工修订」 | 可打开的真实 GLB；新成果需输入校验值与输出运行编号配对 |
| 7–18 秒 | 展示该场景的参考图与交互结果，观察角色、姿态和道具 | 「这里可以对照画面，观察主体之间的空间关系。」旧图注明是旧场景渲染；无经验证相机时注明「默认视角，非原图相机」 | 对应图像和场景；匹配原图相机的说法仅用于有相机证据的成果 |
| 18–29 秒 | 保持完成结果可见，配上该运行的一项 Astra 判断与对应输出细节 | 有证据才说「这项判断影响了这里的输出」。当前仅有旧场景时继续展示交互，并标明「新流程 Astra 作用尚未验证」 | 真实请求、响应与输出关联；仅有调用记录不证明判断生效 |
| 29–42 秒 | 有真实修正案例时切换同一运行的前后产物；否则从另一角度展示已完成场景的一处局限 | 只描述日志与画面共同支持的具体修正；无证据时明确「自动修正尚未验证」 | 同一运行修正前后文件与可见差异；不能拼接无关运行冒充修正 |
| 42–53 秒 | 旋转、重置视角、展示场景下载 | 「从侧面观察，也可以下载三维文件。」旧场景重置称「默认视角」 | 实际页面操作、真实下载和文件重新打开结果；未验证的操作不进入成片 |
| 53–60 秒 | 展示第二个已完成 demo；只有一个时继续展示该场景，并显示核实的比赛新增项与项目地址 | 「本次新增：」后只列有提交差异和运行证据支持的贡献。旧素材与既有手工场景单独标为已有基础 | 新增工程功能以提交差异和实际功能为据；新生成或修正成果必须有本次运行证据；地址须实际可访问 |

60 秒是剪辑分配，不是生成耗时。预生成标签贯穿展示，录屏标注「预录交互画面」。只有旧场景时可制作已有成果的演示草稿，但不能宣称已展示本次自动生成贡献；新贡献证据补齐后再定稿。

## 三分钟现场演示

| 现场时间 | 操作与讲解 |
| --- | --- |
| 0–25 秒 | 打开已完成的交互 demo，旋转到侧面。说明用途与预生成属性；旧场景持续标注「已有预生成场景，姿态经人工修订」。 |
| 25–55 秒 | 对照该 demo 的参考图，指出角色数、左右关系、姿态、道具和环境。旧参考图说明是旧场景渲染；无验证相机时只使用「默认视角」措辞。 |
| 55–90 秒 | 继续操作完成场景，指出一项有真实记录支持的 Astra 判断及其输出影响；尚无新证据时展示已有场景的细节与局限，并明确新流程作用尚未验证。 |
| 90–125 秒 | 切换第二个已完成 demo，比较不同主体或环境；只有一个可用场景时展示其另一角度和遮挡区域，明确单帧背面属于补全。不得把另一张候选输入当作已生成成果。 |
| 125–155 秒 | 在完成结果中旋转、重置、对照并下载。只对有相机证据的结果展示原图视角匹配。有真实修正前后产物才展示修正效果，否则指出一处仍不精确的地方。 |
| 155–180 秒 | 显示核实的比赛新增贡献与公开项目地址。报告所展示运行的实际耗时与费用，未知就说未知；旧场景缺少可靠历史耗时和费用。用一句话说明限制，停在可旋转场景。 |

## 两分钟问答准备

| 评委问题 | 回答依据 |
| --- | --- |
| Astra 做了什么？ | 展示真实响应中的一个判断以及对应输出变化。Astra 调用存在不等于它改变了三维输出。当前旧场景没有本次流程的 Astra 证据。 |
| 哪些是本次比赛做的？ | 指向本次提交和实际新增功能；生成与修正主张还需运行记录。旧图与旧手工场景是已有基础，不能充当新流程证据。 |
| 是实时生成吗？ | 场景在演前准备完成，现场是实时交互，视频是预录交互画面。pipeline 是团队内部真实的准备工具；运行耗时从对应证据读取。 |
| 能处理任意图片或纯文字吗？ | 只回答实际完成运行覆盖的输入范围与失败案例。七张候选图不等于七次生成成功；纯文字能力须有独立成功运行证据。 |
| 背面为什么长这样？ | 单帧没有提供背面证据，背面是补全；原图对照只验收可见部分。 |
| 素材能用吗？ | Sintel 原帧 © Blender Foundation，按 CC BY 3.0 保留署名、许可链接与改动说明，商标不在该许可内。双人测试图为项目方确认本次可使用，不另行授予通用开源许可。逐图来源与改动见素材目录。 |
| 花多少钱？ | 分别读取 Astra 与其他生成服务的实际计费或可核查估算；未知费用明确说未知，不显示零。旧场景的历史耗时和费用均未知。 |
| 能下载继续编辑吗？ | 以真实下载和重新打开的检查结果回答，不能把 GLB 内嵌资源的文件核验说成当前网页下载已验证。 |

## 演前准备与定稿条件

先核实集成页面中的已完成 demo 可交互、可对照和可下载，确认公开仓库与 demo 地址。每个展示结果保留来源、许可、预生成标签及限制；旧场景没有经验证的原图相机，不承诺相机匹配。

通过团队内部 pipeline 在演前准备新成果，保留输入校验值、输出运行编号、实际模型与服务调用、判断如何影响输出、修正前后产物以及耗时费用。第二组完成结果与真实修正案例仅在证据齐全时加入脚本；缺少时按表内当前成果段落演示，明确尚未验证的能力。新流程贡献没有证据时，不将草稿宣称为已证明比赛新成果的成片。

录制真实交互页面，保留原始录屏与一分钟成片，持续显示预录及预生成标记；拍摄与现场均按完成结果排练。当前草稿不代表已经录制、发布或通过实际集成验证。
